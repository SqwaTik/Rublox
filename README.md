# Roblox AI Assistant

AI-ассистент для разработки игр в **Roblox Studio**: чат с поддержкой
**Claude / ChatGPT / локальных моделей**, мост к плагину Studio, слеш-команды
и компрессия контекста для экономии токенов.

## Возможности

- 💬 Постоянный чат с сохранением истории и резюмированием (`/compact`).
- 🗂 Мультичаты с сайдбаром (создание/переключение/удаление), история на диске.
- 🖥 Десктоп-приложение (Electron) со сворачиванием в трей / скрытые значки.
- 🎨 Интерфейс glassmorphism, markdown-форматирование, подсветка и копирование кода.
- 🔌 Подключение к Roblox Studio через плагин (long-poll, без открытых портов).
- ⬇ Авто-установка плагина (`.rbxm`) прямо в папку плагинов Roblox одной кнопкой.
- 🤖 Anthropic / OpenAI / любые кастомные провайдеры + настройки в самом UI.
- 🧩 Мини-пикер модели (как в Codex): указал токен — подтянулись рабочие модели.
- ⚡ Стриминг ответа токен-за-токеном (SSE).
- 🧠 Уровень «мышления» (minimal/low/medium/high) вместо температуры.
- 🛠 Инструменты: `run_code`, `insert_model`, `get_console_output`, `get_studio_context`, `start_stop_play`, `run_script_in_play_mode`, `use_template`.
- 🪙 Экономия токенов: оглавление проекта, агрессивное сжатие истории, шаблоны кода.
- 💻 Локальный режим (`/local`) при отключённом Roblox.

## Архитектура

```
  Веб-чат (web/)  ──WebSocket──►  Сервер-мост (server/)  ──HTTP API──►  LLM
        ▲                              ▲
        │                              │ long-poll
        └── статус Studio              ▼
                              Плагин Studio (plugin/)
```

Плагин не принимает входящих соединений — он сам опрашивает сервер
(`/api/roblox/poll`), выполняет команды и присылает результат
(`/api/roblox/result`). Это совместимо с песочницей Studio.

## Установка и запуск

```bash
cd roblox-ai-assistant
npm install
cp .env.example .env      # на Windows: copy .env.example .env
```

Откройте `.env` и заполните ключи:

- `ANTHROPIC_API_KEY` — для Claude;
- `OPENAI_API_KEY` — для ChatGPT;
- для локальной модели укажите `LOCAL_BASE_URL` (Ollama/LM Studio/vLLM);
- `BRIDGE_TOKEN` — произвольный токен, его же введёте в плагине.

Запуск сервера:

```bash
npm start
```

Откройте <http://localhost:8787> — это веб-чат.

## Десктоп-приложение (трей)

```bash
npm install            # подтянет electron + electron-builder
npm run desktop        # запуск в режиме разработки
```

Приложение запускает сервер внутри себя, открывает окно и живёт в системном
трее (скрытые значки). Крестик прячет окно, а не закрывает — вернуть через
двойной клик по иконке в трее или пункт «Открыть». Полный выход — пункт «Выход».

### Сборка .exe

```bash
npm run build          # установщик NSIS → dist/Roblox AI Assistant Setup <ver>.exe
npm run build:dir      # распакованная версия → dist/win-unpacked/
```

Готовый установщик появится в `dist/`. Данные приложения (сессии, провайдеры,
сборка плагина) в упакованной версии пишутся в `%APPDATA%\Roblox AI Assistant`.

> Подсказка для Windows: если `electron-builder` падает на распаковке
> `winCodeSign` (ошибка симлинков `libcrypto.dylib`/`libssl.dylib`) — это нужно
> только для подписи под macOS. Включите Developer Mode или распакуйте архив
> кэша вручную; на саму сборку под Windows эти файлы не влияют.

## Как это работает (это не Rojo)

Rojo генерирует файлы на диске и синкает их в плейс. Здесь иначе: плагин через
мост выполняет Lua **прямо в открытом DataModel** твоего плейса. Когда ты
пишешь «сделай спринт на Left Shift», AI создаёт **постоянный** `LocalScript` в
`StarterPlayer.StarterPlayerScripts` — он остаётся в плейсе и работает при
запуске Play, без выхода из места и без внешних файлов. Серверная логика идёт в
`ServerScriptService`, общие модули — в `ReplicatedStorage`.

## Установка плагина одной кнопкой

В сайдбаре — кнопка «⬇ Установить плагин» (или клик по статусу «Studio:
отключён»). Сервер собирает `build/AIAssistantPlugin.rbxm` и копирует его в папку
плагинов Roblox (`%LOCALAPPDATA%\Roblox\Plugins` на Windows). Перезапусти Studio —
плагин появится на вкладке Plugins. Дальше нажми в нём Connect.

## Подключение плагина Studio

1. Откройте `plugin/AIAssistantPlugin.server.lua`.
2. В Roblox Studio: **Plugins → Save as Local Plugin** (или скопируйте в папку плагинов).
3. В **Game Settings → Security** включите **Allow HTTP Requests**.
4. Откройте панель плагина (кнопка *AI Chat*), укажите URL сервера
   (`http://localhost:8787`) и токен из `.env`, нажмите **Connect**.
5. Индикатор в веб-чате сменится на «Studio: подключён».

## Провайдеры и кастомные модели

Встроены три провайдера (`anthropic`, `openai`, `local`). Любой
OpenAI- или Anthropic-совместимый сервис добавляется через файл
`providers.json` в корне проекта:

```bash
cp providers.example.json providers.json   # Windows: copy ...
```

Каждый провайдер описывается так:

```json
{
  "id": "openrouter",
  "label": "OpenRouter",
  "kind": "openai",                         // "openai" | "anthropic" — протокол
  "baseUrl": "https://openrouter.ai/api/v1",
  "apiKeyEnv": "OPENROUTER_API_KEY",        // ключ берётся из .env
  "model": "anthropic/claude-3.5-sonnet"
}
```

`kind` задаёт протокол, а не вендора: `openai` подходит для OpenRouter, Groq,
Together, Mistral, DeepSeek, Fireworks, vLLM, Ollama, LM Studio и т.п. Ключ
можно указать прямо (`apiKey`) или сослаться на переменную окружения
(`apiKeyEnv`). Кастомные провайдеры появляются в выпадающем списке UI и
доступны через `/models` и `/model <id>`. Файл `providers.json` в `.gitignore`.

## Стриминг

Ответ модели приходит токен-за-токеном через SSE и наращивается прямо в баббле
чата (с мигающим курсором). Работает для обоих протоколов — `anthropic`
(события `content_block_delta`) и `openai` (chunked `delta.content`). Tool-calls
собираются из стрима инкрементально и выполняются после завершения блока.

## Экономия токенов

- Модель сначала запрашивает `get_studio_context` (краткое оглавление дерева),
  а не весь исходный код — это даёт основную экономию.
- История диалога автоматически сворачивается в тезисное резюме при превышении
  порога `CONTEXT_COMPRESS_THRESHOLD`.
- `/context` позволяет явно дать нужную информацию вместо длинных сообщений.
- **Шаблоны кода** (`/templates`, инструмент `use_template`): частые конструкции
  (платформер, NPC, гонка, лидерборд, сбор предметов) берутся из готовой
  библиотеки `server/templates.js`, а не генерируются с нуля.

## Play-режим

- `start_stop_play` / `/play` / `/stop` — управление плей-тестом. Studio не даёт
  плагину публичного API для программного запуска F5, поэтому инструмент сообщает
  текущий режим и подсказывает нажать F5/Shift+F5, а также определяет, идёт ли тест.
- `run_script_in_play_mode` / `/playrun <lua>` — выполнение кода во время теста
  (проверка игровой логики на работающем сервере).

## Хранение сессий

История, резюме и настройки автоматически пишутся в `data/sessions/<id>.json`
после каждого сообщения и восстанавливаются при следующем запуске сервера.
Каталог `data/` в `.gitignore`. `/reset` очищает и историю, и файл.

## Безопасность

- Команды в Studio выполняются только по запросу из чата и логируются в панели плагина.
- Локальное выполнение (`/local`) выключено по умолчанию (`ALLOW_LOCAL_EXEC=false`).
- Запросы к серверу-мосту авторизуются токеном `BRIDGE_TOKEN`.

## Структура проекта

```
server/
  index.js        — HTTP + WebSocket + REST для плагина
  config.js       — конфигурация и загрузчик .env
  bridge.js       — очередь команд и long-poll к плагину
  agent.js        — агентный цикл с tool-use
  session.js      — сессии, история, компрессия
  store.js        — сохранение/загрузка сессий на диск
  context.js      — оценка токенов и резюмирование
  templates.js    — библиотека готовых Lua-шаблонов
  commands.js     — слеш-команды
  llm/
    providers.js  — Anthropic / OpenAI / local + стриминг
    registry.js   — реестр провайдеров (providers.json)
    tools.js      — описания инструментов
web/              — веб-чат (HTML/CSS/JS)
plugin/           — плагин Roblox Studio (Lua)
data/             — сохранённые сессии (создаётся автоматически)
```
